# Laboratory Activity 9: Reflection

### 1. Why is automation critical when managing hundreds of cloud servers?

Automation is important because managing hundreds of cloud servers manually takes a lot of time and effort. With automation, we can run commands and perform tasks automatically without doing everything one by one. It also helps reduce human errors and makes server management faster and easier. For me, automation is useful because it allows cloud engineers to focus on other important tasks.

### 2. What are the dangers of automation?

Even though automation is helpful, it can also be dangerous when a script contains a mistake. For example, if a destructive command runs on 1,000 servers, it could delete important files or damage many systems at once. This is why scripts should be checked and tested before running them on real servers. I learned that automation needs careful planning because one small mistake can cause a big problem.

### 3. How did writing a Bash script differ from writing the Docker Compose file in Lab 6?

Writing a Bash script in Lab 9 was different from creating a Docker Compose file in Lab 6. The Bash script was used to automate commands, such as backing up important files. Meanwhile, the Docker Compose file was used to define and manage multiple containers, such as the Nextcloud application and its database. Both are useful, but they have different purposes.

### 4. How has your understanding of cloud computing changed from Lab 1 to Lab 9?

From Lab 1 to Lab 9, my understanding of cloud computing has improved. At first, I only had a basic idea of how cloud systems worked. Through the activities, I learned about containers, storage using MinIO, server monitoring, security, and automation. I also experienced problems like Docker permission errors and issues pulling MinIO images. These experiences taught me that cloud computing requires patience, problem solving, and proper system management.

### 5. Which cloud computing role did you enjoy most, and why?

The role I enjoyed most was Cloud Operations Engineer because I learned how to monitor server resources and check container activity. In Lab 7, I used commands to check memory usage, storage, logs, and container performance. I found this interesting because it helped me understand how to check whether a server is working properly. Overall, these activities gave me a better understanding of the skills needed to manage cloud systems.
