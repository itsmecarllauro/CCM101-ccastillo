# Laboratory Activity 2: Build the Cloud Infrastructure Blueprint

## Mission Overview
This laboratory activity focused on investigating the components of cloud
infrastructure as part of CloudNova Technologies' first official project.
The mission involved exploring a Linux server environment to understand how
compute, storage, networking, and identity services work together, and
documenting these findings as if preparing technical documentation for a
client planning to migrate services to the cloud.

## Objectives
- Explain the major components of cloud infrastructure
- Investigate the hardware and software resources available in a Linux environment
- Differentiate compute, storage, networking, and identity resources
- Interpret the relationship between cloud infrastructure components
- Create professional technical documentation using Markdown
- Continue building a structured GitHub Cloud Computing Portfolio

## Cloud Infrastructure Components
- **Compute Resources** — CPU/processing power that runs applications and services
- **Storage Resources** — Persistent storage for data and files
- **Networking Resources** — Connections that allow communication between systems
- **Operating System** — Manages hardware resources and runs applications

## Tools Used
- KillerCoda Playground (Linux environment)
- GitHub (version control and portfolio hosting)
- Draw.io (cloud architecture diagram)
- Markdown (documentation)

## Linux Commands Executed
`lsb_release`, `uname`, `lscpu`, `free`, `df`, `mount`, `hostname`, `git`, `mkdir`, `touch`, `nano`

## Skills Learned
Through this activity, I learned how to investigate a Linux server's
infrastructure details, differentiate between cloud infrastructure
components, compare major cloud providers (AWS, Azure, GCP), and design a
simple cloud architecture diagram. I also practiced maintaining organized
technical documentation in Markdown.

## Challenges Encountered
One challenge was understanding how compute, storage, and networking
components relate to each other within a single Linux environment. Another
was researching and accurately comparing services across AWS, Azure, and
GCP, since each provider uses different naming conventions for similar
services.
